# Readme

The implemented prototype has been created with the use of a Hex notebook, ideal for quickly adapting and evolving components as it is particularly suited towards data analytics and has fantastic in-built version control and quick deployment of solutions. 

## Build instructions

The Hex file format represents the logic of my entire project (including the layout of an app) as a YAML file. It’s fully compatible with all features of Hex, but just as a note it does not contain any potentially sensitive outputs of my project. To build and deploy the prototype, I strongly recommend re-importing it as an identical project into Hex. It is already deplyed live and both the code as well as the app can be viewed on the repository at https://app.hex.tech/b4df83f5-9a77-4bb2-892c-7f5eac3642a3/hex/791db296-9a10-4eae-b4ea-a363e7ca92da/draft/logic. 

There is also a jupyter notebook included in the GitHub repository that creates the synetic data which is used for the back-end of my project. Running this is recommended to get a sense of the scope of the back-end, however entirely unnecessary for the build since data is stored on Google Sheets and pulled in via their API. 

For more detail on re-importing Hex apps, refer to the documentation stored here: https://learn.hex.tech/docs/explore-data/projects/import-export#import-a-new-version-of-a-project.
